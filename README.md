# Moventure

[![Support on Ko-fi](https://img.shields.io/badge/Ko--fi-Support%20Marcelo%20Souza-ff5e5b?logo=ko-fi&logoColor=white)](https://ko-fi.com/msouza3d)

Live: **[kumodot.github.io/moventure](https://kumodot.github.io/moventure/)** (library, player, studio).

A pocket gamebook platform: a small device with a 128x64 OLED and six buttons
(D-pad + A + B) that loads interactive "choose your path" books. You read, turn
pages, and at certain moments you decide, and the decision changes where the story goes.

This repo is the **PC side** of the project: everything is simulated in the browser
before any hardware is touched.

```
Moventure/
├─ run_sim.bat                double-click to test: rebuilds stories.js + player and opens the newest simulator
├─ run_studio.bat             rebuilds and opens Moventure Studio (the book editor)

    ├─ build_player.py        builds the single-file player from the newest sim + stories.js
```

## Online

The library portal, player and Studio are static files served from `docs/` by GitHub Pages:
`https://kumodot.github.io/moventure/`. `tools/build_site.py` rebuilds `docs/` from the newest
simulator, the newest Studio and every validated book in `stories/` (via `catalog.json`).
`publish.bat` rebuilds everything, commits and pushes. Links worth knowing:

- `player/?player=1&book=<id>` opens a book's cover (what the portal's Play buttons do)
- `player/?player=1&add=<url-of-a-book.json>` adds any Moventure book to that browser's
  library and opens it (the target for QR codes)

## Reading your own books

Books you add yourself live on the **My books** shelf of the LIBRARY (right after All), kept in
that browser. Three ways in: **Load a book** in player mode (or drag a `.json` onto the page),
a QR / `?add=` link, or **Open in Player** inside the Studio, which hands the book over with no
file at all. Menu > **Remove book** takes one off the shelf.

## Quick start

1. Double-click `run_sim.bat` (or open the newest `simulator/moventure_sim_v*.html`).
2. The device boots into the LIBRARY. Left / Right changes the shelf (category), Up / Down picks
   a book, A shows its cover (category, tier, blurb), A again starts it.
3. Read with A / Right (next page), B / Left (previous page). On the last page of a node,
   A opens the choice menu. Up / Down picks, A confirms, B goes back to the text.
4. B on the first page of a node opens the MENU (Resume, Stats, Restart, Library, About).
   In tier 3 books, UP while reading opens the STATS sheet directly; stat changes flash on the
   status bar (`+3 LUCK`, `-1 GRIT`).
5. Dice: when a choice is a roll, the DICE screen tumbles a cube and settles on the pip face
   (`5+2=7 vs 4 PASS`). A continues. Tier 3 books track stats (menu > Stats).

Keyboard: arrows = D-pad, A (or Z / Enter / Space) = A, B (or X / Backspace / Esc) = B.
Gamepad (Steam Deck, Xbox, PS): d-pad or left stick, A, B.

## Player mode and sharing

"Player mode" (header button, or `?player=1`) hides everything except the device and scales it
to the window; Fullscreen is one click. For friends and the Steam Deck, send the single file
`simulator/moventure_player_vX.Y.Z.html`: all books are inlined, it needs nothing else and
starts in player mode. Host it anywhere static (GitHub Pages, a Drive link) for a URL.

The right side of the page is the **live story map**: the graph under the book. The current
node is highlighted, the path you took is drawn in yellow, dashed edges are choices with a
`require` condition. Below it you see the flags that are set and the list of nodes visited.
Use "Load JSON" to drop in any story file, the OLED colour selector to match the panel you buy.

## Writing books: Moventure Studio

`run_studio.bat` opens the editor. It is a manuscript, not a diagram: write the story top to
bottom. When the reader should decide, put the cursor where the text splits, open the ⋯ menu
and pick **Fork here**: what follows becomes path A and an empty path B opens for you.
**Random event here** splits the same way but the dice decide (paths P and F). Each path has
a code made of the choices that lead there (A, B, A-B, A-P…), folds to one line, and opening
one folds the others, so you always look at one path at a time. Finish every path with
**The End** or **Go to** another path (same menu). An output can be hidden "only if the
reader went through A-B". The device on the right plays what you write; the Check panel says
what is missing in plain words. **Open in Player** reads the book on the real player (My books
shelf); Export JSON gives a `stories/*.json` to share or to drop in `stories/` for `run_sim.bat`.

## Generating books with the tools

```bash
# generate a book from a theme (starship | tomb | forest | random) and tier (1 | 2 | 3)
python tools/moventure_gen.py --theme tomb --tier 2 --seed 42 -o stories/my_tomb.json --mermaid

# check any book (broken links, dead ends, stuck states, labels too long for the screen)
python tools/validate_story.py stories/my_tomb.json

# rebuild the simulator bundle so the new book shows up in the LIBRARY
python tools/build_stories_js.py
```

The generator builds every book on the same skeleton (arrival, a hub with 2-3 side
locations, a locked gate, a confrontation with 5 possible endings) and randomises which
location hides the key, which has the ally, which is the trap, plus the flavour text.
Adding a theme is adding one dict to `THEMES` in `moventure_gen.py`.

Hand-written books are better than generated ones. Three references, one per tier:

| book | tier | category | what it shows |
|---|---|---|---|
| The Hollow Lighthouse | 1 | Horror | flags gating choices, 8 endings, all reachable |
| The Last Train to Halvard | 2 | Mystery | dice rolls without stats (lockpick, force, bluff, ledge) |
| The Bronze Gate | 3 | Fantasy | luck / aim / grit, a potion, a bow, a combat loop with grit loss |

The validator proves every ending is reachable by walking every node + flag combination.

**Foundation Files** is the SCP series: eleven books adapted from SCP Foundation articles
(087, 173, 096, 049, 106, 914, 682, 3008, 1730, 2521, 1471), each under CC BY-SA 3.0 with the
original author credited in `meta.based_on`. Every SCP's rule is a mechanic: blink rolls in
173, never writing the number in 2521, days that cost food in 3008.

## Book tiers (see STORY_FORMAT.md)

Tier 1 = choices only. Tier 2 = choices + dice. Tier 3 = choices + dice + stats that
evolve through the story (a potion raises LUCK, a bow raises AIM, a hit costs GRIT).
Higher tiers are strictly supersets, so one engine reads all three.

### Writing books with an LLM

The format is small enough to paste into a prompt. Give the model `STORY_FORMAT.md`,
the lighthouse JSON as an example, a theme, and ask for "a Moventure book with N nodes,
M flags and K endings, every ending reachable". Run `validate_story.py` on the result;
it catches the mistakes LLMs usually make (labels too long, dead ends, a flag required
that is never set).

## Languages

Books are multilingual by design: every text can carry `en`, `pt` and `es` versions in the
same file (see STORY_FORMAT.md). Two separate settings on the device: the interface language
(menu > Language: EN / PT-BR / ES, remembered) and the book language, picked per book among
what the author provided (Left / Right on the cover, or menu > Book while reading), like
picking the audio track of a film. In the Studio, the EN / PT-BR toggle switches what you are writing and shows
the other language as a hint. The three hand-written books ship in both languages. The
device font has all the accented letters and ç; curly quotes and dashes are normalized.

## Screen rules (128x64, 5x7 font)

| | |
|---|---|
| status bar | row 0-7: node title left, page counter right, underline at y=7 |
| text | 7 rows x 21 columns starting at y=9 |
| choice menu | up to 6 visible choices, scrolls beyond that |
| choice label | 19 chars max |
| node title | 15 chars max |

`validate_story.py` and the simulator use the same word-wrap function, so page counts
match. When the firmware is written, port `wrap()` and the `OLED` class 1:1 and run the
cross-validation from `OLED_SIMULATOR_GUIDE.md` section 8.

## Roadmap

- [ ] Firmware: ESP8266 first (boards on hand, cheapest), ESP32-S3 as the upgrade path. SSD1306 I2C, 6 buttons, deep sleep between presses, books in flash (LittleFS).
      The `Engine` class in the simulator is written to be ported as-is.
- [ ] Book packer: JSON -> compact binary for the microcontroller (strings + edge table).
- [x] v2 format: tiers, dice, stats.
- [ ] Inventory as a first-class list (today: flags), timed events, per-book save slots.
- [ ] Visual node editor (drag the map, edit text in place).
- [ ] Simple graphics per node (1-bit 40x40 illustrations next to the text).
- [ ] Later: verb-menu adventures (look / move / push / pull / eat) on the same engine.
